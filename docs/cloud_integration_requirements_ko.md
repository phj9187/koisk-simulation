# AI 키오스크 연구 시스템 — GitHub·Google Colab Pro+·Google Drive 통합 실행 환경 구축

## 1. 작업 목표

현재 GitHub 저장소에 연결된 AI 기반 맞춤형 키오스크 추천 최적화 연구 프로젝트의 클라우드 개발 및 실행 환경을 구축한다.

본 프로젝트는 다음 네 가지 서비스를 사용한다.

- **Cloud Codex:** 프로그램 개발, 알고리즘 수정, 코드 검증
- **GitHub:** 소스 코드, 버전, 실험 설정, 실험 결과 요약 관리
- **Google Colab Pro+:** 장시간 시뮬레이션 및 AI 모델 학습
- **Google Drive:** 대용량 실험 데이터, 학습 모델, 체크포인트 저장

사용자는 Google Colab Pro+ 유료 구독을 이용하고 있다.

프로젝트의 목적은 노트북의 CPU 및 RAM 사용을 최소화하면서 클라우드에서 대규모 시뮬레이션을 실행하고, 연구 결과를 체계적으로 축적하는 것이다.

**이번 작업의 최우선 목표는 기존 AI 키오스크 시뮬레이션을 GitHub에서 Google Colab으로 쉽게 실행하고, 실행 결과가 Google Drive와 GitHub에 체계적으로 저장되는 환경을 실제로 구축하는 것이다.**

기존 연구 알고리즘을 임의로 교체하거나 연구 목적을 변경하지 않는다.

## 2. 기존 GitHub 저장소 확인

먼저 현재 연결된 GitHub 저장소를 조사한다.

다음 내용을 확인한다.

1. 기존 프로젝트의 폴더 구조
2. 현재 구현된 시뮬레이션 코드
3. 고정 가중치 모델과 상황별 가중치 모델
4. AI 학습 알고리즘
5. 실험 설정 및 결과 저장 방식
6. 기존 GitHub 브랜치 및 최근 변경 사항
7. Google Colab 실행에 필요한 의존성

기존 코드와 연구 내용을 가능한 한 보존한다.

이미 구현된 기능은 중복해서 만들지 않고, 새 클라우드 실행 환경에 맞게 재사용한다.

저장소가 비어 있다면 기존 연구 계획을 기준으로 기본 프로젝트 구조를 구성한다.

기존 저장소에 연구 내용이 불충분한 경우 임의로 수학적 모델을 확정하지 말고 기본 가정과 미확정 사항을 문서화한다.

## 3. 전체 시스템 아키텍처

다음 흐름으로 시스템을 구성한다.

```text
Cloud Codex
    │
    │ 코드 작성·수정
    ▼
GitHub Repository
    │
    │ Open in Colab
    ▼
Google Colab Pro+
    │
    ├── 시뮬레이션 실행
    ├── AI 모델 학습
    ├── 고정 가중치 모델 평가
    ├── 상황별 가중치 모델 평가
    └── 결과 분석
    │
    ├──────────────────────┐
    ▼                      ▼
Google Drive            GitHub
    │                      │
    ├── 원시 데이터         ├── 실험 요약
    ├── 모델 가중치         ├── 비교 그래프
    ├── 체크포인트         ├── 실험 설정
    └── 상세 로그           └── 코드 버전
```

GitHub를 전체 개발 과정의 중앙 저장소로 사용한다.

Colab은 GitHub의 특정 코드 버전을 가져와 실행하고, 실험 데이터를 Google Drive에 저장한다.

각 실험은 GitHub 커밋 해시와 고유 실험 ID로 추적할 수 있어야 한다.

## 4. Google Colab Pro+ 실행 환경 구축

사용자는 Colab Pro+ 구독을 이용하고 있으므로 다음 조건을 고려한다.

### 4.1. 장시간 실행

Colab Pro+에서 제공되는 장시간 및 백그라운드 실행 기능을 활용할 수 있도록 설계한다.

다만 Colab Pro+도 무제한 실행이나 런타임 지속성을 보장하지 않는다.

따라서 시스템은 실행 환경이 종료되더라도 실험을 복구할 수 있도록 설계해야 한다.

Colab에서 허용되는 최대 실행 시간, 사용 가능한 메모리, GPU 및 컴퓨팅 유닛은 실제 실행 환경에 따라 달라질 수 있음을 고려한다.

### 4.2. 연산 자원 최적화

기본적으로 CPU 실행을 지원한다.

GPU가 유리한 학습 알고리즘을 사용하는 경우 GPU 실행도 선택할 수 있도록 설계한다.

불필요한 GPU 사용을 피하고, GPU 사용 전후의 실행 시간과 연산 효율을 비교할 수 있도록 한다.

학습 데이터 처리에 메모리를 과도하게 사용하지 않도록 배치 처리 또는 스트리밍 방식도 고려한다.

### 4.3. 실행 환경 정보 기록

실험 시작 시 다음 정보를 기록한다.

- Python 버전
- 주요 라이브러리 버전
- CPU 및 GPU 정보
- 사용 가능한 메모리
- 실행 시작 시간
- 사용한 Git 커밋 해시
- 실험 설정
- 난수 시드

## 5. GitHub에서 Colab 실행

GitHub 저장소의 다음 경로에 실행 노트북을 구성한다.

`notebooks/run_simulation.ipynb`

노트북은 다음 기능을 제공해야 한다.

1. GitHub 소스 코드 불러오기
2. 특정 커밋 버전 선택
3. 라이브러리 설치
4. Google Drive 인증 및 연결
5. 실험 설정 인터페이스 표시
6. 시뮬레이션 시작
7. 실행 중 진행 상황 확인
8. 중지 요청 처리
9. 체크포인트 저장
10. 중단된 실험 재개
11. 결과 분석 및 시각화
12. GitHub 실험 기록 생성

GitHub README.md 상단에 공식 `Open in Colab` 배지를 추가한다.

사용자가 GitHub에서 버튼을 클릭하면 해당 노트북을 Google Colab으로 열 수 있어야 한다.

단, GitHub에서 Colab을 여는 것과 실제 런타임을 시작하는 것은 별개의 과정이다.

공식적으로 지원되지 않는 Colab 자동 실행 API를 임의로 가정하거나 비공식적인 브라우저 자동화로 실행하도록 구현하지 않는다.

## 6. Colab 사용자 설정 인터페이스

Google Colab에서 실행할 때 사용자가 별도의 Python 코드 수정 없이 실험 조건을 설정할 수 있어야 한다.

ipywidgets 등을 사용해 다음 항목을 제공한다.

- 하루 방문자 수
- 비교 대상 모델
- 난수 시드
- 체크포인트 저장 간격
- 상세 로그 기록 여부
- 실험 결과 시각화 여부
- 신규 실험 시작 또는 기존 실험 재개

가능한 경우 버튼 형태의 실행 인터페이스를 제공한다.

- 실험 시작
- 안전 중지 요청
- 최근 체크포인트에서 재개
- 결과 확인

**시뮬레이션 중지는 하루 단위 경계에서 이루어져야 한다.**

중지 요청이 발생하면 현재 진행 중인 하루를 완료한 뒤 데이터를 저장하고 종료한다.

Colab 특성상 실행 중인 셀과 사용자 인터페이스 사이의 상호작용에 제약이 있을 수 있으므로, 실제로 동작하는 안전 중지 방식을 구현하고 테스트한다.

## 7. 장시간 시뮬레이션 및 복구

시뮬레이션은 하루를 기본 반복 단위로 사용한다.

사용자가 종료 일수를 별도로 지정하지 않으면 명시적인 중지 요청 또는 런타임 종료가 발생할 때까지 실행하도록 한다.

단, 연구 시스템은 실행 환경 종료를 정상적인 운영 상황으로 처리할 수 있어야 한다.

### 7.1. 체크포인트

체크포인트는 Google Drive에 저장한다.

체크포인트에는 다음 정보를 포함한다.

- 실험 ID
- 완료된 시뮬레이션 날짜
- 모델별 학습 파라미터
- 모델별 재고 상태
- 누적 실험 결과
- 난수 생성기 상태
- 실험 설정
- 코드 버전
- 필요한 경우 옵티마이저 상태

### 7.2. 복구 기능

사용자가 동일한 실험을 다시 실행하면 마지막 유효한 체크포인트를 읽어 이어서 실행할 수 있어야 한다.

중복 데이터가 생성되지 않도록 한다.

실험 설정이나 코드 버전이 이전 실행과 다르면 호환성 검사를 수행한다.

체크포인트가 손상되었을 때 이전의 유효한 체크포인트에서 복구할 수 있도록 가능한 범위에서 백업한다.

### 7.3. 저장 효율

매 고객 처리마다 Google Drive에 직접 기록하는 방식은 지양한다.

Colab의 임시 저장소에서 데이터를 처리한 뒤, 적절한 주기로 Google Drive에 일괄 저장한다.

다만 체크포인트 저장 시점 사이에 런타임이 비정상 종료되면 일부 진행 상태가 유실될 수 있다는 한계를 문서화한다.

## 8. Google Drive 구조

다음 구조를 자동 생성하도록 한다.

```text
MyDrive/
└── AI-Kiosk-Data/
    │
    ├── raw_data/
    │
    ├── experiments/
    │   ├── EXP-0001/
    │   │   ├── metadata.json
    │   │   ├── daily_metrics.parquet
    │   │   └── detailed_results/
    │   │
    │   └── EXP-0002/
    │
    ├── checkpoints/
    │
    ├── models/
    │
    └── backups/
```

실험 데이터는 가능하면 효율적인 Parquet 형식을 사용한다.

모든 실험에는 고유 ID를 부여한다.

데이터 저장 오류 발생 시 해당 오류를 기록하고 가능한 범위에서 재시도하며, 저장에 실패한 상태를 성공으로 보고하지 않는다.

## 9. GitHub 결과 기록

실험별 요약 자료는 GitHub에 저장한다.

권장 구조:

```text
results/
├── summaries/
│   ├── EXP-0001/
│   │   ├── metadata.json
│   │   ├── summary.csv
│   │   ├── comparison.png
│   │   └── report.md
│   │
│   └── EXP-0002/
│
└── experiment_registry.csv
```

기록할 정보:

- 실험 ID
- 실행 날짜
- Git 커밋 해시
- 난수 시드
- 하루 방문자 수
- 비교 모델
- 총 실행 일수
- 모델별 주요 성능 지표
- 실험 요약
- 원시 데이터의 Google Drive 저장 위치

GitHub에는 작은 요약 자료만 저장한다.

대용량 로그, 모델 가중치 및 체크포인트는 Google Drive에 저장한다.

### GitHub 자동 반영

Colab에서 실험 결과를 GitHub에 기록하는 기능을 구현한다.

인증에는 Colab Secrets에 저장된 최소 권한 GitHub 토큰 등을 사용한다.

토큰을 코드나 노트북 출력에 노출하지 않는다.

기본 브랜치에 직접 무조건 커밋하기보다는, 결과 기록 전용 브랜치를 사용하거나 Pull Request를 생성하는 안전한 방식을 우선 고려한다.

인증 정보가 없는 경우에도 실험 자체는 실행할 수 있어야 한다.

이 경우 GitHub 업로드를 건너뛰고, 업로드할 결과물을 Google Drive에 보관하도록 한다.

## 10. AI 키오스크 연구 모델 유지

이번 작업에서는 기존 연구의 핵심 비교 구조를 유지한다.

비교 대상은 다음 두 모델이다.

1. 고정 가중치 모델
2. 상황별 가중치 모델

고객 선호도, 고객 만족도, 매장 운영 효율성, 재고와 관련된 기존 설계를 검토한 뒤 적용한다.

가중치, 목적함수, 학습 알고리즘이 아직 정해지지 않았다면 이를 임의로 연구의 최종 설계로 확정하지 않는다.

두 모델은 동일한 외생적 실험 조건에서 비교해야 한다.

단, 추천 결과에 따라 변화하는 재고나 모델 내부 상태는 각각 독립적으로 관리한다.

실험 결과를 통해 상황별 가중치 모델의 우수성이 검증되는지 객관적으로 판단할 수 있어야 한다.

임의의 결과 데이터를 만들어 성공한 실험으로 기록하지 않는다.

## 11. 성능 분석 및 시각화

최소한 다음 그래프를 지원한다.

- 날짜별 고객 만족도 변화
- 모델별 평균 만족도 비교
- 가중치 변화 추이
- 모델별 학습 성능 변화
- 재고 및 운영 효율성 변화
- 실험 기간에 따른 성능 차이
- 반복 실험 결과 비교

정의되지 않은 지표는 임의로 추가하지 않는다.

그래프는 Colab에서 확인할 수 있어야 하고, 주요 결과는 GitHub에 PNG 등의 형식으로 저장한다.

원시 데이터와 통계 분석 결과는 Google Drive에 저장한다.

## 13. 구현 우선순위

다음 순서로 작업한다.

**1단계 — 기존 저장소 분석**

현재 프로젝트와 코드를 확인한다.

**2단계 — Colab 실행 환경**

GitHub 노트북 실행 구조와 README의 Open in Colab 버튼을 구현한다.

**3단계 — Google Drive 연결**

대용량 데이터 및 체크포인트 저장 구조를 구성한다.

**4단계 — 시뮬레이션 통합**

기존 AI 키오스크 시뮬레이션을 Colab에서 실행한다.

**5단계 — 중지 및 복구**

하루 단위 중지, 체크포인트, 실험 재개 기능을 구현한다.

**6단계 — 결과 기록**

GitHub에 실험 요약과 그래프를 기록한다.

**7단계 — 통합 검증**

테스트와 사용 방법 문서를 작성한다.

## 14. 최종 완료 기준

최종적으로 다음 사용자 경험을 구현한다.

1. 사용자가 GitHub 저장소에 접속한다.
2. `Open in Colab` 버튼을 누른다.
3. Google Colab Pro+ 환경에서 노트북을 연다.
4. GitHub 코드와 Google Drive 데이터를 연결한다.
5. 하루 방문자 수 등의 실험 조건을 입력한다.
6. 실행 버튼을 누른다.
7. 클라우드에서 시뮬레이션과 AI 학습이 진행된다.
8. 장시간 실행 중 데이터와 체크포인트가 Google Drive에 저장된다.
9. 사용자가 중지를 요청하면 하루 단위로 안전하게 종료한다.
10. 이후 같은 실험을 체크포인트에서 다시 시작할 수 있다.
11. 실험 결과와 비교 그래프를 확인한다.
12. 주요 결과가 GitHub에 기록된다.

## 15. Codex 실행 지침

이 작업은 단순한 설계 문서 작성이 아니라 실제 작동하는 통합 실행 환경 구축을 목표로 한다.

현재 연결된 GitHub 저장소를 먼저 확인한 다음 작업을 진행한다.

기존 소스 코드를 가능한 한 유지한다.

필요한 코드를 실제로 작성하고 테스트한다.

Colab이나 Google Drive의 인증이 필요한 부분은 사용자 개입이 필요한 단계로 구분하여 문서화한다.

외부 서비스에 직접 접근할 수 없는 경우에도 필요한 실행 노트북, 설정 코드, 저장 모듈, 테스트 코드를 작성한다.

GitHub 연동을 위한 인증 정보는 사용자에게 안전한 설정 방법을 안내한다.

프로젝트가 완성되면 다음 내용을 보고한다.

- 변경된 파일 목록
- 구현된 기능
- GitHub에서 Colab을 여는 실제 링크
- 최초 실행 시 필요한 인증 및 설정
- Google Drive 저장 경로
- 테스트 결과
- 실제 Colab 환경에서 아직 검증하지 못한 부분
- 현재 시스템의 제약 사항

작업을 계획서 작성만으로 끝내지 말고, 현재 환경에서 가능한 구현과 테스트를 모두 수행한다.
