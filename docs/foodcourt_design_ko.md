# 대학 푸드코트 모형과 학습 편향 점검

## 목적과 범위
손님이 만족하고 푸드코트 전체의 공헌이익도 늘어나는 추천을 찾는다. 점수가 오르는 것만으로 성공이라고 판정하지 않는다. 기존 kiosk_sim과 이전 실험은 보존하고 kiosk_foodcourt를 새 실험으로 추가했다.

연세대의 실제 공개 메뉴명·가격, 세종대의 여러 음식 코너와 메뉴 규모, 한양대 ERICA·연세대 미래캠퍼스의 운영시간, 순천대의 키오스크 주문·결제·식권 흐름 등을 참고한 **가상 대학**이다. 서로 다른 학교·식당·연도의 자료를 합성했다. 특정 학교를 재현하거나 실제 효과를 예측하는 디지털 트윈이 아니다. 공식 출처와 확인 범위는 src/kiosk_foodcourt/data/sources.json, 메뉴별 출처·공개가격 여부는 menu_anchors.json에 있다.

세종대 2026 안내의 코너별 '대표 메뉴 외 N종'을 합산하면 64종이다. 이것은 규모 설정의 참고값이며, 생성한 64개 메뉴가 세종대의 실제 메뉴 전체와 같다는 뜻은 아니다. 공개 메뉴를 넘어선 변형 메뉴와 미공개 가격은 가상값으로 표시한다. 사이드 메뉴를 독립 식사로 세지 않는다.

## 한 끼 운영 흐름
손님 도착 → 공용 키오스크 대기 → 메뉴 탐색·추천 수용/거부 → 결제 시점 재고 확인 → 코너별 조리 대기 → 조리 → 공용 좌석 대기 → 식사 시작.

시간순 사건 처리로 키오스크·조리원·좌석을 공유한다. 기다리다 포기, 예산 초과, 알레르기 제약, 품절, 운영 종료, 수업까지 남은 시간, 추천 거부를 포함한다. 두 키오스크가 같은 마지막 재료를 보더라도 결제 시 재확인하므로 재고를 중복 소비하지 않는다.

12·32·64개 메뉴를 비교한다. 같은 반복 안에서는 큰 메뉴판이 작은 메뉴판을 포함하며, 메뉴가 늘어도 인력·총 준비량은 늘지 않는다. 기본은 4개 코너, 키오스크 2대, 코너당 조리원 2명, 좌석 200석, 180분 식사 시간대다. 실제 학교에서 측정된 수치라는 의미가 아니다.

맛 취향, 추천 수용률, 조리시간, 레시피, 재료비, 재고, 선호 추정 오차, 수업 시간과 도착 분포는 모두 가정이다. 알레르기 표시는 모형용 가상 태그이며 실제 음식의 성분 정보가 아니다. 점심시간 운영 모형이며 하루 전체·방학·주간 수요를 검증한 모형은 아니다. 앱 주문, 여러 끼에 걸친 유통기한, 실제 레시피별 조리 병목은 아직 포함하지 않았다.

## 알고리즘
6개 비교군: 추천 없음, 과거 판매 기반 인기 추천, 손님 가치만 고려하는 추천, 연구자가 정한 고정 가중치, 학습한 고정 가중치, 상황에 따라 가중치가 달라지는 학습 추천.

학습은 CEM(좋은 후보를 남기며 탐색 범위를 바꾸는 반복 탐색)이다. 고정형은 5개 점수의 가중치를, 상황형은 손님의 가격·대기 민감도와 시간·혼잡·재고에 따른 가중치 변화를 학습한다. 신경망 정확도를 측정하는 분류 문제가 아니다. 손님 특성을 완벽히 관찰할 수 있다는 강한 가정이 있으므로, 실제 적용에는 설문·주문 기록을 이용한 추정과 추가 검증이 필요하다.

매 세대 새로운 학습용 식사 시간대를 생성하고 탐색 분포와 검증으로 선택한 정책을 저장한다. 같은 실험을 재실행하면 이전 세대에서 계속한다. 고정형과 상황형의 후보 수×학습 일수는 같다. 손님 단위 미래 맛·미래 주문·미래 조리 결과를 추천에 미리 전달하지 않는다. 맛 추정에는 같은 오차를 넣고 모든 비교군이 같은 정보를 쓴다.

학습 / 정책 선택용 검증 / 마지막 평가의 난수 영역을 나눈다. 최종 평가나 스트레스 평가 결과는 가중치 선택으로 되돌리지 않는다. 검증을 반복 사용하므로 검증집 과적합 가능성은 남는다. 발표용 확증 실험은 설계를 고정한 후 새 seed와 새 결과 폴더에서 실행해야 한다.

## 편향 방지와 판정
- 모든 정책을 같은 외부 손님·조리 변동 조건에서 비교한다. 개인의 선택에 따라 실제 대기열은 달라질 수 있다.
- 제한된 메뉴 탐색과 전체 탐색을 모두 실험한다. 선택 복잡도를 높여 AI가 무조건 유리하도록 설계하지 않는다.
- 추천 수용은 확률적이며 추천 화면에도 시간이 든다. 추천이 손해가 되는 결과도 그대로 저장한다.
- 손님 점수는 방문자 전체가 분모다. 구매자만 남겨 만족도가 높아 보이는 현상을 피한다. 이탈자는 0점 처리하는 모형상 가치 판단이며 별도 이탈 건수도 함께 본다.
- 학습 벌점과 검증 선택에 전체 손님뿐 아니라 상대적으로 예산이 적은 집단·대기에 민감한 집단의 손실을 반영한다. 기준은 손님 중심 추천 대비 점수 하락 0.01 이내다. 이 허용치는 합의된 실제 최소 차이가 아니라 수정 가능한 연구 가정이다. 예산 집단은 설정된 예산 범위의 중간값으로 나눈다.
- 가중합의 상승만으로 공동 개선이라 하지 않는다. 손님 점수 변화와 원 단위 공헌이익 변화를 분리하며 엄격한 동시 상승과 비열등 조건을 구분한다. 평균 공동 개선 표시는 하위 집단의 무해성을 보장하지 않으므로 집단 변화도 확인한다.
- 공헌이익 = 매출 − 사용 식재료비 − 남은 준비 식재료의 가정된 폐기 비용. 임대료·인건비를 뺀 순이익이 아니다. 코너별 매출도 저장하며 푸드코트 전체 개선이 모든 입점업체의 개선을 뜻하지 않는다.
- 학습이 끝난 같은 정책을 낮은 수용률·큰 취향 추정 오차·조리/좌석 부족·낮은 폐기율에서 다시 시험한다. 이 결과는 각 작업 result.json의 stress_test에 있으며 정책 재학습에 쓰지 않는다.
- 반복 캠퍼스를 독립 단위로 집계한다. 독립 캠퍼스 5개 미만이면 오차 구간을 표시하지 않는다. 제공하는 정규근사 구간은 설명용이며, 다중 비교를 보정한 공동 유의성 증명은 아니다.

## Colab Pro
notebooks/run_foodcourt_colab.ipynb를 사용한다. pilot으로 실행 확인 후 colab 설정을 선택한다. 기본 대규모 설정은 20개 독립 캠퍼스 × 메뉴 수 3 × 탐색 방식 2 × 방문 규모 2 = 240개 작업이며 각 작업의 고정·상황형을 100세대씩 학습한다. 많은 반복 자체가 현실 정확도를 보장하지는 않는다.

이 모형은 NumPy 기반 CPU 실험이다. GPU를 선택해도 자동으로 빨라지지 않으며 Colab Pro의 자원과 연결 시간은 보장되지 않는다. 2개 작업을 병렬 처리하고, 한 번에 처리할 작업 수와 시간 예산을 지정한다. 시간 제한은 세대 사이에 확인하므로 강제 종료 시각이 아니다. 모델·설정이 바뀌면 새 실험 이름을 사용한다. 모델 파일과 설정의 지문이 다르면 기존 결과에 이어 쓰지 않는다.

Drive를 사용하면 사용자가 직접 인증한다. 결과는 jobs/작업이름/checkpoint.json, result.json, court.json과 summary.json에 남는다. 갑작스러운 연결 종료로 잠금이 남으면 다른 작업이 실행 중이지 않은지 확인한 후 해당 worker.lock만 제거한다. 원시 고객 사건 전체를 대량 저장하지 않고 집계 결과와 학습 상태를 저장한다.

실행 예:
```
python -m kiosk_foodcourt.cli --config config/foodcourt_colab.yaml --root /content/drive/MyDrive/kiosk_foodcourt/research_001 --plan
python -m kiosk_foodcourt.cli --config config/foodcourt_colab.yaml --root /content/drive/MyDrive/kiosk_foodcourt/research_001 --max-jobs 4 --time-budget-minutes 20
```

모든 가정은 models.Settings에서 확인할 수 있고 YAML로 바꿀 수 있다. 선호 가중치·폐기율 등을 바꾼 결과를 함께 보고, 실제 학교의 주문·대기·폐기 기록이 확보되면 그 기록으로 보정해야 한다. 공개 메뉴 자료만으로 손님 행동까지 실측했다고 해석하면 안 된다.
