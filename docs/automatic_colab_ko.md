# GitHub → Colab 자동 실행 및 저장·복구

## 처음 실행

1. [자동 실행 Colab 열기](https://colab.research.google.com/github/phj9187/koisk-simulation/blob/main/notebooks/run_automatic.ipynb).
2. 본인 Google 계정으로 로그인하고 CPU 런타임에 연결합니다.
3. **런타임 → 모두 실행**을 누릅니다. Drive 권한 요청을 승인합니다.
4. 기본 `PRESET="pilot"`은 8매장·9개 평가 조건·15명·학습2/검증1/평가1일·1반복을 실행하고 종료합니다.
5. 연구 실행은 새 런타임에서 `PRESET="research"`로 설정한 뒤 실행합니다. 8매장·9조건·30명·20/5/5일·5반복이며 가상 고객 자료입니다. 조사 자료를 자동으로 대체하거나 실측이라고 표시하지 않습니다.

공개 GitHub 저장소의 코드를 읽는 데 토큰은 필요 없습니다. 비공개인 경우만 Colab Secrets의 `KIOSK_GITHUB_TOKEN`에 해당 저장소 읽기 권한 토큰을 등록합니다. GitHub 요약 업로드는 선택 사항이며 쓰기 권한이 필요합니다. 토큰을 채팅에 붙여넣지 마세요.

버튼으로 조건을 바꾸고 싶다면 [대화형 노트북](https://colab.research.google.com/github/phj9187/koisk-simulation/blob/main/notebooks/run_simulation.ipynb)을 사용합니다. 기본 평가 기준은 동일한 9개입니다.

## 저장 위치

Drive의 `MyDrive/AI-Kiosk-Data/` 아래에 저장됩니다.

| 경로 | 내용 |
| --- | --- |
| `latest_run.json` | 가장 최근 상태를 갱신한 실험의 위치와 진행 요약 |
| `experiments/ID/progress.json` | 마지막 UTC 갱신 시각·완료 날짜·완료 매장·체크포인트 날짜·상태 |
| `experiments/ID/metadata.json` | 설정·코드 커밋·소스 해시·환경 정보 |
| `experiments/ID/detailed_results/` | 일별 결과 Parquet와 선택한 경우 고객 로그 |
| `checkpoints/ID/day_*.json` | 완전한 날짜의 복구 지점 |
| `checkpoints/ID/partial_*/` | 아직 완전한 복구 지점에 포함되지 않은 매장별 진행 상태 |
| `models/ID/` | 최신 정책과 반복별 학습 종료 정책 |
| `experiments/ID/summary_exports/` | 종료/중지 후 CSV·JSON·그래프·교차평가 |
| `experiments/ID/cleanup_last.json` | 마지막 자동 정리의 삭제·보존 목록 |
| `experiments/ID/session_result.json` | 자동 실행의 결과 경로와 종료 사유 |

`running` 표시만으로 런타임 생존이 보장되지는 않습니다. 강제 종료 시 마지막 상태가 남으므로 갱신 시각과 Colab 연결 상태를 함께 확인합니다. 여러 실험을 동시에 실행하면 latest_run은 가장 최근에 상태를 쓴 실험이며, 개별 실험 상태는 각 progress.json에서 확인합니다.

## 체크포인트와 자동 정리

- `checkpoint_every`: 완전한 날짜 기준 저장 주기. 학습/검증 경계 및 종료·정상 중단에도 저장합니다.
- 매장별 부분 결과는 각 매장이 끝날 때 저장하여 강제 종료 손실을 줄입니다.
- `checkpoint_keep`: 최신 복구 지점 보관 수. 최소 2, 기본 2입니다.
- `auto_cleanup`: 기본 true. 저장 파일과 참조 결과의 체크섬을 확인한 후 정리합니다.
- 가장 오래 보존하는 복구 지점까지 이미 포함된 부분 스냅샷을 정리합니다. 그 이후의 부분 결과는 손상 시 대체 복구를 위해 남깁니다.
- 같은 실험 결과 폴더 안에서 어떤 보존 체크포인트도 참조하지 않고, 확정된 결과와 **바이트가 동일한** Parquet 복사본만 자동 삭제합니다.
- 고유한 날짜 자료·고객 로그·학습 종료 모델·알 수 없는 파일·다른 실험 폴더는 자동 삭제하지 않습니다.
- 같은 논리 키의 완전히 같은 결과 행은 합치되, 같은 키에 서로 다른 값이 있으면 오류로 중지합니다.
- 전체 결과를 매번 복사한 `daily_metrics.parquet`를 새로 만들지 않고 일별 파일을 원본으로 사용합니다. 구버전 실험의 파일을 훑어 삭제하지 않습니다.
- 보존 지점과 참조 자료가 손상됐으면 정리 성공으로 처리하지 않습니다.

Drive는 외부 파일 시스템이므로 원자적 파일 교체와 체크섬이 모든 클라우드 장애를 예방하는 것은 아닙니다. 중요한 실험은 별도 백업도 권장합니다.

## 중지와 재개

오늘 완료 후 멈추려면 대화형 노트북의 중지 버튼 또는 다음 코드를 사용합니다.

```python
from pathlib import Path
experiment_id = "EXP-여기에실험ID"
(Path(DATA_ROOT) / "experiments" / experiment_id / "STOP").write_text("stop")
```

런타임을 강제로 중단해도 저장된 날짜·매장 부분 결과에서 재개합니다. 새 런타임에서:

1. `REVISION`을 progress.json 또는 metadata.json의 정확한 `git_commit`으로 설정합니다.
2. `RESUME_ID`에 실험 ID를 넣습니다.
3. 모두 실행하고 Drive를 다시 승인합니다.
4. 원래 설정을 복원해 이어 실행합니다. `RESUME_ID`를 비우면 별도의 새 실험이 시작됩니다.

`RUNNING.lock`이 남았다는 오류가 나오면 이전 Colab 런타임이 완전히 종료됐는지 먼저 확인합니다. 종료가 확인된 경우에만 해당 실험의 잠금 파일을 수동 삭제합니다. 다른 런타임이 실행 중인데 잠금을 지우면 자료 충돌 위험이 있습니다.

같은 코드를 사용하더라도 Python·의존성 버전이 달라지면 엄격한 복구 검사가 거부할 수 있습니다. 다른 버전으로 조용히 이어서 재현 가능한 것처럼 처리하지 않습니다.

## 평가 기준과 교차평가

9개 screening 조건에서 학습합니다. 중간 가중치 3개는 학습에 넣지 않고 교차평가용으로 보관합니다. 추가 기준을 무작정 자동 생성하거나 대규모 학습으로 확대하지 않습니다.

교차평가는 저장된 원시 성과를 이용하므로 추가 고객 시뮬레이션이 필요 없습니다. 각 정책의 입력 λ는 `policy_lambda`로 고정하고, 모든 후보의 점수 비교에는 동일한 `evaluation_lambda=0.5`를 사용합니다. 이는 설명용 공통 평가값이며 사회적으로 공정한 정답은 아닙니다.

`cross_evaluation.csv`에는 학습 시나리오·평가 시나리오·정책 λ·재평가 점수·후회·순위를 저장합니다. `robustness.csv`의 상위권 비율은 선언한 시나리오를 동일 비중으로 계산한 값이며 실제 고객의 비율이 아닙니다. 후회는 같은 반복·모델의 탐색된 후보 내 최고 점수 대비이며 전역 최적 대비가 아닙니다. 이 분석은 가게들을 평균한 성과에 대한 분석이고 가게별 선호 교정은 별도 연구입니다.

최종 평가의 교차평가는 기술적 분석입니다. 이를 보고 최종 운영 정책을 선택하거나 모델을 수정했다면 별도의 새 최종 평가 자료가 필요합니다.

## 자동 실행의 실제 범위

인증 이후 셀이 실행되는 동안 시뮬레이션과 저장·정리는 자동으로 진행됩니다. Colab/Pro+는 런타임 유지나 무제한 실행을 보장하지 않으며, 종료 후 재개는 사용자가 수행해야 합니다. 자동 실행 노트북은 런타임 종료를 우회하지 않습니다.

현재 Codex 도구에는 사용자의 Google 로그인 브라우저 제어가 없습니다. 개발 환경에서의 테스트·GitHub 푸시와 사용자 계정의 실제 Colab 실행 여부는 구분합니다. 이후 Codex에 진행 상황을 물을 때 Drive가 도구로 연결되지 않았다면 해당 `progress.json`과 필요시 오류 기록을 공유해야 정확히 확인할 수 있습니다.
