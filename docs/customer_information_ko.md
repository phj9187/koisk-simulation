# 손님 행동 수정안의 검토와 구현

## 채택한 부분과 해석

전체 메뉴·진짜 맛·실제 주방 상태를 손님이 정확히 안다는 가정은 완화할 수 있다. 다만 기존 손님 효용식과 고객 평가 점수의 식은 다르고 선택 잡음도 있으므로, 기존 모델에서 추천 효과가 수학적으로 불가능하다고 단정하지 않는다. AI의 오차를 손님보다 작게 두는 것도 관측 사실이 아니라 실험 조건이다. 개선율 3% 같은 목표를 강제하거나 결과가 나오도록 계수를 맞추지 않는다.

모듈 `customer_model.py`로 고려 집합·맛/대기 인식·수락·탐색시간·신뢰 갱신을 분리했다. 기존 설정은 그대로 두고 새 정보 제한 가정은 `actor_critic_customer_information_pilot.yaml`에서만 켠다. 새 결과는 schema 9와 새 실험 ID로 기록한다. 이전 실험의 재개에는 당시 코드가 필요하다.

## 설정

| 설정 | 기본값 | 의미 |
|---|---|---|
| consideration_mean | null | null이면 전 메뉴, 숫자면 min(N, 1+Poisson(mean))개를 고려 |
| salience_position / salience_category | 0 / 0 | 앞쪽 배치·방문 목적에 따른 노출 확률 가정 |
| salience_popularity | 빈 사전 | 메뉴별 사전에 고정된 로그 현저성. 미래 주문이나 평가 결과로 만들지 않음 |
| taste_noise / ai_taste_noise | 0 / 0 | 손님·AI의 맛 적합도 추정 오차. 어느 쪽이 더 작아야 한다는 제한 없음 |
| regular_taste_noise | null | 재방문 고객의 별도 오차. null이면 일반 손님과 같음 |
| decision_rule | legacy | 기존 선택시간 유지. inspected는 실제 살펴본 메뉴 수로 결정 |
| decision_base / decision_per_item | 0.8 / 0.25 | inspected 방식의 공통 시간 공식(분) |
| overload_penalty | 0 | 고객 점수에서 γ log(1+살펴본 수)를 차감. 대기 성분과 별도 피로 가정 |
| wait_visibility | full | full은 기존 실제 주방 상태. menu_only는 메뉴 조리시간만, visible_queue는 관찰 가능한 키오스크 대기의 조리시간 대리지표 |
| wait_noise | 0 | 손님 대기 추정의 평균 보존 로그정규 오차 |
| trust_learning / trust_rate | false / 0.1 | 재방문 고객의 수락한 추천에서 실제 맛과 예상 맛의 오차로 신뢰 갱신 |

맛 오차는 손님과 AI에 서로 다른 고정 난수 흐름을 적용하고 0~1로 제한한다. 실제 식후 취향 점수는 진짜 적합도로 평가한다. AI에 진짜 고객 취향과 주방 상태를 제공하는 기존 정보 구조 역시 가정이다. 이것을 실측으로 학습한 개인 취향 추정기로 표현하지 않는다.

## 선택 순서와 시간의 일관성

고려 집합은 중복 없이 노출 가중치에 따라 뽑는다. 추천은 집합 밖의 메뉴도 노출할 수 있다. legacy 시간 모드는 기존처럼 고려 집합의 최선과 추천을 비교한다. inspected 모드에서는 손님이 먼저 본 메뉴와 추천 후보를 평가하고 수락하면 탐색을 끝낸다. 거절하면 고려 집합의 나머지도 살펴본다. 따라서 수락 판단에서 아직 보지 않은 메뉴의 최댓값을 미리 사용하지 않는다. 로그의 own_choice는 전체 고려 집합을 끝까지 보았을 때의 반사실적 선택이다.

세 비교군 모두 `기본시간 + 메뉴당시간 × 살펴본 고유 메뉴 수`를 적용한다. 추천이 거절되면 추가 후보 때문에 더 오래 걸릴 수도 있다. 추천이라는 이유만으로 고정 시간 이득을 더하지 않는다. 피로는 보상 계산과 학습 피드백에 같은 식으로 반영한다. 평가기준을 바꾸어 재평가할 때도 날짜별 성분을 보존해 0 하한 처리 후 가중 평균하므로, 평균에 하한을 잘못 적용하지 않는다.

신뢰 이력은 같은 유한 에피소드 안의 반복 방문자에게만 유지하고 모델별로 분리한다. 독립 에피소드의 미래 방문·주문을 보지 않는다. 메뉴별 장기 경험 학습이나 무한 기간 고객 관계 모델은 아니다.

## 미구매 원인과 검증

`no_feasible_menu`에 재고·예산·알레르기 실패를 비트마스크로 남긴다. 한 제약만 완화했을 때 구매 가능한 메뉴가 생기는지도 따로 집계한다. 여러 제약이 겹칠 수 있어 세 비율의 합을 100%로 해석하면 안 된다. 이전 1270일 실행은 상세 로그가 없어 약 30% 미구매를 예산 때문이라고 확정할 수 없다. 예산 분포는 진단 전에 자동 확대하지 않았다.

수정 전 코드에서 만든 9개 고정 기준 추적으로, 새 가정을 끈 경우 기존 숫자와 주문·추천 결과가 같은지 검사한다. 추가 검사는 노출·인식과 실제 맛 분리·순차 탐색·대기 정보·피로 보상·날짜 간 저장 후 재개를 다룬다.

`tools/customer_model_audit.py`는 고정 고객·재고·난수에서 미추천, 균등 가중치, 다섯 단일 요소 가중치, 실제 즉시 고객 효용을 아는 탐욕적 추천을 비교한다. 마지막 정책은 미래 재고·주문·대기까지 최적화한 전역 상한이 아니다. 비교군에 같은 정보 제한을 적용하고 AI 오차가 더 작은 경우는 별도 조건으로 표시한다. 이 자료로 학습 정책을 고르거나 성능을 튜닝하지 않는다.


## 고정 표본 점검 결과

실제 자료 pilot의 8개 매장 템플릿에서 별도 고정 고객 표본 3개씩을 생성해 비교했다. 기존 행동 가정의 미추천 기준은 총 3,771명 중 826명이 가능한 메뉴 없음, 1,348명이 대기 포기였다. 826명 모두 예산 제약만 완화하면 가능한 메뉴가 하나 이상 생겼다. 34명은 알레르기 제약만 완화해도 다른 대안이 생겼으므로 원인이 겹친다. 이 수치는 이전 synthetic 1270일 결과의 원인을 소급 확인한 것이 아니다. 예산 분포를 관측 자료 없이 자동 확대하지 않았다.

고려 집합만 제한했을 때 균등 추천의 고객 점수 차이는 +0.001337, 매장 점수 차이는 +0.005396이었다. 손님·AI에 동일한 0.25 오차를 적용하면 균등 추천의 고객 점수 차이는 -0.000130으로 바뀌었다. 탐색 중단·대기 비가시성 조건에서도 균등 추천의 고객 차이는 -0.000424였고, 즉시 고객 효용을 아는 탐욕적 기준은 +0.007363이었지만 매장 점수는 -0.007795였다. 모두 해당 고정 표본과 balanced 평가기준에서의 **절대 점수 차이**이며 일반적인 효과율이나 신뢰구간이 아니다.

같은 비교군의 C/S에 λ를 적용한 기술적 외피에서는 매장 비중이 클 때 마진 위주, 고객 비중이 클 때 고객 효용 위주 기준이 유리했다. 이 표본으로 학습 정책이나 계수를 선택하지 않았다. 정보 제한은 추천 효용의 가능성을 만드는 가정이지만, AI의 개선을 보장하는 장치는 아니다.

## Colab 출력 경로

실험 실행과 외부 iframe 표시를 분리했다. 노트북의 SHOW_LIVE_UI 기본값은 false이며 텍스트로 완료 에피소드 수와 저장 위치를 출력한다. 저장된 model_board.html과 모델별 상세 스크립트는 dashboard_bundle.zip 하나로 묶는다. iframe 표시가 안 되는 브라우저에서도 계산과 저장을 진행할 수 있다. USE_DRIVE를 끄면 임시 런타임 폴더를 쓰며, 연결 종료 전에 결과를 내려받아야 한다. Drive 연결 실패 시 조용히 임시 저장으로 바꾸지는 않는다.
