# 현실 조건 확장과 검증

기존 synthetic 1270일 실험은 원래 조건으로 보존한다. 이 변경은 새 실험 ID와 schema 8을 사용하며 이전 결과와 합치지 않는다. 모든 행동 계수는 별도의 고객 관측 자료로 보정하기 전까지 가정이다.

## 실행 구조

`Config.realism`에서 현실 조건을 설정한다. 빈 설정은 하루 에피소드·단일 추천·선택시간 추가 부담 없음·대기 포기 없음·고정 조리시간이다. `config/actor_critic_realistic_pilot.yaml`은 여러 날 재고를 포함하는 검증용 설정이다.

재고 이월을 켜면 한 기록 단위는 여러 연속 날짜로 구성된 유한 에피소드다. 에피소드 사이에는 같은 초기 재고로 다시 시작한다. 각 에피소드의 달력 구간은 겹치지 않으며 학습·구간선택·검증·평가 에피소드는 별개다. 고객별 모델은 날짜 사이에도 다음 상태의 가치를 이어 평가하고 마지막 날짜에만 종료한다. 하루 고정 모델은 날짜별 행동의 할인 누적 보상으로 학습한다. 무한 기간의 최적 발주 정책을 구현한 것은 아니다. 발주는 공통 기준재고 정책이며 추천 모델의 행동은 여전히 추천 가중치다.

재고는 일별 FIFO 묶음으로 관리한다. 남은 수량을 이월하고 보관기간이 끝나면 폐기한다. 마감 후 기준재고까지 발주하며 다음 날 입고한다. 입고 충족률로 외부 공급 부족을 설정할 수 있다. 원가·수명·비용·공급 충족률은 가정값이다. 기말 남은 재고는 보유 자산이며 실제 폐기로 취급하지 않는다. 유한 기간 경계에서 발생하는 효과는 기간을 바꾸어 확인해야 한다.

여러 날 목적함수는 고객 점수와, 순마진 및 실제 폐기 비율을 이용한 매장 점수를 결합한다. 순마진은 판매마진에서 폐기재고 원가·폐기비·보관비를 차감한다. 입고 구매액은 별도 현금흐름 항목이며 판매원가와 중복 차감하지 않는다. 마진 성분은 `.5 + .5 * 순마진 / 기준최대마진`을 0~1로 제한한다. 이 점수는 기존 하루 모델의 점수와 척도가 다르다. 결과를 섞어 순위를 매기지 않는다. `profit`은 전체 에피소드의 순마진 합계, C/S/R은 날짜별 점수의 평균이다.

## 행동·운영 가정

- 상위 1~3개를 추천하고, 고객은 제시된 후보 중 자신의 효용과 고정된 개인별 선택 잡음으로 하나를 고른 뒤 수락 여부를 결정한다. 선택시간의 추천 추가 부담은 별도 변수다. 기본 비교에서는 미추천과 같은 선택시간 공식을 유지한다.
- 대기 한도는 지수분포와 고객의 대기 민감도로 정한다. 키오스크 입장 전과 주문 확정 전에 예상 대기를 보고 포기할 수 있다. 실제 대기 도중 포기하는 정교한 사건 시뮬레이션은 아니다.
- 조리시간은 메뉴 평균을 중심으로 로그정규 변동을 줄 수 있다. 수요에도 평균을 보존하는 로그정규 충격을 더한 뒤 포아송 방문자를 생성할 수 있다.
- 좌석 수를 설정하면 매장 이용 고객은 빈 좌석을 기다린다. 한 고객이 한 좌석을 사용하며 단체·테이블 병합은 가정하지 않는다. 식사 후 점유시간도 설정값이다.
- 반복 방문 비율을 설정하면 같은 취향의 고객 묶음이 재방문하고 추천 수용도에 설정된 보너스를 더한다. 구매 이력에 기반한 충성도 학습이나 개별 고객 식별 시스템은 아니다.

난수는 고객·수요·재고·입고·조리시간별로 분리하고 모델 간에 공유한다. 독립 반복의 신경망 초기화 seed는 반복 번호로 분리한다. 연속 학습 사이클은 독립 반복으로 집계하지 않는다. 다섯 번 반복했다는 이유만으로 정확한 신뢰구간이 보장되지는 않는다.

## 자료와 적용 범위

- KREI 2025 외식업 경영실태 원자료: 매장 donor 표본의 관측 항목. 공식 원본 SHA256을 검사한다. 메뉴 원가·조리시간·맛·행동계수 전부가 실측된다는 뜻은 아니다.
- [서울시 추정매출-상권](https://data.seoul.go.kr/dataList/OA-15572/S/1/datasetView.do): 시간대별 및 요일별 **매출 건수**를 수요의 대리지표로 사용한다. 일곱 요일의 상대 비율과 시간대 분포를 분리해 적용하는 것은 결합분포를 관측한 것이 아니라 분리 가능성 가정이다. KREI의 전국 표본과 서울시 상권을 실제 동일 매장으로 연결하지 않는다.
- [서울시 생활인구](https://data.seoul.go.kr/dataList/OA-15439/S/1/datasetView.do): 특정 시점에 지역에 존재하는 인구로, 매장 유입 고객 수가 아니다. 날짜·시간별 관측에서 평일·주말 시간대 분포를 만들고 매출 분포와 선택적으로 결합한다. 결합 강도는 가정이며 기본 pilot에 자동 적용했다고 주장하지 않는다.
- [경기도 카드매출 시간대 집계](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=88UZJGHAP6WFG5TSOBP338234799&infSeq=1): 서울 이외 지역의 외부 검증 후보. 실제 원본을 확보하고 기간·업종·건수/금액을 확인하기 전에는 한국 전체 수요로 사용하지 않는다.
- [미국 Census 외식업 매출과 계절조정 계수](https://www.census.gov/retail/marts/www/adv72200.txt): 금액 자료이며 방문자 수가 아니다. 한국 기본 수요에 합산하지 않고 해외 계절성의 별도 스트레스 시나리오로만 사용한다.
- [OpenTable 식당 수요 지표](https://www.opentable.com/c/state-of-industry/): 현재 방법은 온라인 예약으로 착석한 고객의 전년 동일 요일 대비 변화다. 2024년 6월 이전의 전 채널 집계와 비교 범위가 다르며, 키오스크·테이크아웃 고객 전체를 대표하지 않는다. 자료 조사 근거로 보존하며 자동으로 한국 수요에 이식하지 않는다.

원본·변환본의 경로, 용량, SHA256과 URL은 `raw_data/sources.json`에 기록한다. 실행 metadata에는 실제 사용한 입력 파일의 해시와 설정을 별도로 기록한다. 파일 내용이 달라지면 같은 실험 ID로 재개하지 않는다.

## 진단·분석·화면

수렴 검사는 실제 실행과 같은 환경 생성기를 사용하지만, 별도의 난수 이름과 고정 표본·달력·재고를 사용한다. 안정성이 최적성이나 현실 정확도를 보장하지는 않는다.

`learning_diagnostics.csv`는 학습 전·후·미추천·규칙 추천의 추천 변경률, 주문 변경률, 수락률, 점수 차이를 기록한다. 상세 고객 사건은 `diagnostic_events.jsonl`로 저장한다. `behavior_sensitivity.csv`는 수락도·선택시간·추천 부담·대기 한도·조리 변동·수요 변동에 대한 고정 표본 검사다. 진단 표본으로 모델이나 λ를 선택하지 않는다.

매장 분석에는 원가율·위험·메뉴 수·맛 좌표와 미추천 대비 ΔC/ΔS/ΔR을 추가한다. 적은 매장 수에서의 계수는 탐색적 연관성이고 인과효과가 아니다. 대기시간은 좌석 대기·키오스크 대기·선택시간·조리 대기·조리시간으로 나누어 저장한다.

실시간 화면은 Colab 연결 외에도 저장된 `live/model_board.html`과 `live/cards`를 함께 열어 볼 수 있다. 모델별·λ별 상세 이력도 저장한다. Colab iframe 표시 오류가 나면 오류 기록을 남기고 저장본 경로를 안내한다. 실제 Colab 브라우저 확인 여부는 검증 보고서에 따로 기록한다.
