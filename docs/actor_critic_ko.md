# 액터–크리틱 변경

기존 무작위 후보 탐색은 `algorithm: random_search`로 보존한다. 새 실험은 `algorithm: actor_critic`이며 체크포인트 스키마 5를 사용한다. 이전 결과를 신경망 학습 결과로 해석하거나 이전 파라미터를 신경망에 불러오지 않는다.

## 학습 흐름

별도의 Actor와 Critic은 각각 25→16→16→출력 MLP(Tanh)이다. 두 모델의 네트워크 크기는 같다. Actor는 softplus+0.5인 Dirichlet 농도 5개를 출력한다. 학습 중 추천 가중치를 샘플링하고, 평가 중에는 평균 가중치를 쓴다. 메뉴 선택·고객 수락은 기존 시뮬레이터가 계산하며 미분하지 않는다.

개인별 모델은 고객의 취향, 민감도, 목적, 예산, 수락 성향, 재고 압력, 조리 혼잡, 시간, 공개 매장 요약과 λ·평가계수를 입력받는다. 한 고객의 보상을 관측하면 다음 추천 전 TD(0)로 업데이트하며, 마지막 고객 뒤에는 종료 가치 0으로 업데이트한다. 할인율은 유한한 하루 전체 점수를 보존하기 위해 γ=1이다. 실제 운영에서 구매 결과가 늦게 도착하는 비동기 처리는 이 가상 시뮬레이터의 범위 밖이다.

일별 모델은 실제 미래 고객을 보지 않고 하루 시작 매장 상태와 공개 예상 고객 수·대표 고객 특성(취향 .5, 가격 .7, 대기 .6, 수락 .5, 예산 30, 혼합 목적이라는 가정)을 입력받는다. λ별 반사실적 하루 실행마다 한 가중치를 고정한다. 하루의 모든 학습 λ 실행을 모아 Actor와 Critic을 각각 한 번 업데이트한다. 모든 λ는 동일 고객·도착·수락 난수로 시작하며 두 모델은 같은 방문자 기회를 갖는다. 수락·품절 차이 때문에 실제 서비스 수와 개인별 업데이트 횟수는 달라질 수 있다.

기존 보상 Rλ=λ Cα+(1−λ) Sβ를 유지한다. 개인별 보상은 고정된 전체 방문자 수·초기 재고를 분모로 한 누적 평가점수의 차이이므로 고객별 합이 하루 보상과 일치한다. Critic 목표는 r+V(next), 종료 시 r이다. Actor 손실은 −log π(w|s)·stop_gradient(target−V(s)), Critic 손실은 평균 제곱오차의 절반이다. 일별 목표는 하루 Rλ다. Adam 학습률은 Actor 0.0003, Critic 0.001, 기울기 노름 상한은 1이다. 별도 엔트로피 보상은 추가하지 않는다.

## 저장·비교

신경망, 두 Adam 상태, 각 정책 전용 CPU 난수 상태를 압축 텐서(JSON, pickle 미사용)로 저장한다. 검증·평가·수렴 점검·차트는 학습을 동결한다. 재개는 원래 커밋·Python·라이브러리 버전을 요구한다. 새 코랩 노트북은 별도 실험을 만든다. 기본 pilot은 4일 검증용이며, 연구 실행은 research 또는 continual을 명시적으로 선택한다. 기존 1000일 결과와 새 모델 결과는 별도다.

기존 선그래프와 100학습 날짜 안정성 검사는 복원된 신경망의 결정론적 평균 가중치·고정 검증 점수에 적용한다. 1% 안정성은 추천 가중치 총변동거리와 [0,1] 보상 범위에서 사용하는 실험상 허용치이며 보편적인 통계적 수렴 보장이 아니다. 민감도 .5%, 1%, 3%도 함께 기록한다. 신경망의 내부 파라미터가 고정되었다거나 최적 정책이라는 뜻은 아니다.

개인별 온라인 학습일의 점수와 하루 전체로 학습한 일별 모델의 점수는 학습 도중 정책이 달라진다. 최종 성능 비교는 같은 새 가상 날짜에서 동결한 평가 결과로 한다. 학습 속도는 방문자 기회, 업데이트 횟수, 실행 시간을 함께 본다. 합성 환경에서의 효과이며 실측 효과를 보장하지 않는다.

근거: [PyTorch distributions: score-function estimator](https://docs.pytorch.org/docs/stable/distributions.html), [PyTorch Actor–Critic example](https://github.com/pytorch/examples/blob/main/reinforcement_learning/actor_critic.py). 기존 100학습일 안정성 절차의 자세한 정의는 stopping_and_linecharts_ko.md를 따른다.

## 정오까지 실행과 실시간 그래프

`notebooks/run_actor_critic_live.ipynb`은 시간대가 포함된 실제 시각으로 중지한다. 이번 실행은 2026-10-28 12:00 KST(03:00 UTC), 일수 상한 없음, 8매장·9평가기준·30방문자, 20/5/5일 주기다. 시간 제한 실험에서는 수렴 조기 중지만 끈다. 정오가 되면 새 매장을 시작하지 않으며, 이미 계산 중인 매장은 저장한 뒤 중지한다. 따라서 마무리·최종 보고서 생성은 정오를 조금 넘을 수 있다. 중간 날짜의 완료 매장은 부분 체크포인트로 남아 재개 시 재계산하지 않는다.

코랩의 실행 셀에 매장 완료마다 고객 점수·매장 점수·공통 보상의 두 모델 선그래프가 갱신된다. 각 평가기준을 펼쳐서 볼 수 있으며 마지막 점이 일부 매장만 반영하면 임시값으로 표시한다. λ별 평균을 먼저 매장 내에서 계산하고 매장들을 동일 비중으로 평균한다. 이는 학습 진행 기술통계이며 변하는 날짜·λ 입력을 통제한 평가가 아니다. 최종 모델 비교는 동결 평가 날짜를 사용한다.

실험 폴더 `live/index.html`, `live/scores.csv`, `live/status.json`에도 최신 화면·수치·시각을 저장한다. 런타임 종료나 접속 단절 뒤 갱신 시각이 멈췄으면 실시간 실행 중이라고 단정하지 않는다. 이 기능은 Colab 런타임 유지나 9시간 실행을 보장하지 않는다. 실행이 종료될 경우 동일 커밋·실험 ID와 새 미래 중지 시각으로 체크포인트에서 재개한다.
